# FormField

Wires a native control to its label, hint and error. The control stays a plain `input`, `select` or `textarea`; `FormField` adds the text around it and `useFormField` makes the ids that tie them together.

## Usage

```tsx
const field = useFormField({ hint, error });

<FormField field={field} label="Delivery note" hint={hint} error={error}>
  <textarea
    id={field.controlId}
    aria-describedby={field.describedBy}
    aria-invalid={field.invalid}
  />
</FormField>;
```

Pass the same `hint` and `error` to both the hook and the component. `describedBy` lists the hint and error ids that are present; `invalid` is `true` only when there is an error.

## Layouts

`stacked` (default) puts the label above the control. `inline` puts them in a row, for short controls such as "Delivered every". Hint and error wrap onto their own lines under the row, so prefer `inline` for controls without a hint or error.

## Errors

The error has `role="alert"` and an alert icon, so it is announced and never relies on color alone. The text uses the danger-on-surface color.

<Canvas of={Stories.TextareaWithError} />

## Borders

An empty text input or textarea uses `border-control-line` and `rounded-control`, so its edge meets the 3:1 contrast a control needs.

## Accessibility

- The `label` is a real `<label htmlFor>`: clicking it focuses the control, and the control is found by its label.
- The hint and error are read with the control through `aria-describedby`.
- Focus shows the focus ring.

## Do / Don't

| Do                                        | Don't                                  |
| ----------------------------------------- | -------------------------------------- |
| Say what is wrong and how to fix it       | A bare "Invalid"                       |
| Pass the same `hint` and `error` to both  | Set `aria-describedby` by hand         |
| Use `border-control-line` on empty fields | Rely on a fill alone to show the field |
